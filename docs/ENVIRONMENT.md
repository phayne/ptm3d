# PTM3D environment variables

This page lists the `PTM_*` environment variables that a user may need. They are read by the
C++ programs and by the scripts in the repository. A few internal diagnostic variables are not
listed. Almost all are unset by default, and leaving them unset gives the reference behavior,
with results identical to the last digit wherever a reference result exists. The exceptions are
the [kill-switch] entries below. Each of those names a behavior that is on by default, and it is
`=0` (not unset) that restores the older behavior. To check this table against the source, search
`src/` and `scripts/` for `getenv("PTM_` and compare the result with the names below.

Status tags:

- [recommended-ON] (fine polar meshes): validated illumination corrections that are off by
  default so that existing results remain reproducible. **The validated set, used together:**
  `PTM_ILLUM_TRUE_NORMALS=1 PTM_ILLUM_RISE_EPS=1 PTM_ILLUM_RISE_KEPS=0.2
  PTM_ILLUM_RISE_HABS=0 PTM_ILLUM_SEAL_HOLES=1`. Set them for meshes with sub-meter relief.
  The Moon3D runs and tutorial 2 do so through an `engine_env:` block. Do not set
  `PTM_ILLUM_RISE_EPS=1` without `PTM_ILLUM_RISE_HABS=0`. On a 509,337-face polar mesh that
  variable alone increased the number of faces that ever see the Sun by 94%, whereas the full
  set reduced it by 43%.
- [kill-switch]: the behavior is on by default, and `=0` restores the older behavior for a
  regression comparison. Unset does not give the older behavior. These variables accept
  `1`/`true`/`on`/`yes` and `0`/`false`/`off`/`no` (case-insensitive). Any other value stops
  the run with an error at startup, before the illumination pass. An explicit `=1` can stop a
  run on a configuration that does not support the behavior, so a value such as `=false` must
  not be read as a request for it.
- [standard]: a stable, supported setting, used when the situation calls for it.
- [tuning]: a performance or memory setting. The defaults suit most runs.
- [experimental]: implemented, but not part of the validated configuration. Read the linked
  notes before use.
- [legacy]: affects only a legacy mode kept for reproducing older runs.
- [debug]: overrides a safety check or restores a superseded behavior, for comparison tests or
  for reproducing an old result exactly. Not for science runs.
- [internal]: diagnostics and support for the batch-run scripts. Not for end users.

## Setting variables in the configuration file with `engine_env:`

A configuration file may declare the variables its run needs. The model applies them at
startup.

```yaml
engine_env:
  PTM_ILLUM_TRUE_NORMALS: '1'
  PTM_ILLUM_RISE_EPS: '1'
  PTM_ILLUM_RISE_HABS: '0'
  PTM_ILLUM_SEAL_HOLES: '1'
```

The block behaves as follows.

- The block is applied before the configuration itself is parsed, so it can also set
  `PTM_DATA_ROOT`.
- The process environment takes precedence. A variable already exported with a different
  value is left unchanged and the disagreement is printed as `CONFLICT`, so an override on
  the command line still works.
- Every variable is echoed with its disposition (`applied`, `already set`, `CONFLICT`), so
  the run log records the environment that the run used.
- Only `ptm_thermal_sim` reads the block. Other programs and the analysis scripts need the
  variables exported.

## Paths and data

| Variable | Default | Effect | Status |
|---|---|---|---|
| `PTM_DATA_ROOT` | unset | Location of the science-data directory when it is outside the repository. An absolute path in a config is used as given. A relative `data/...` path is looked up first under `$PTM_DATA_ROOT` and then under the repository's `data/`, which is found by walking up from the config file to the directory that contains `data/data_manifest.json`. If a required input is still missing, the program stops with an error that names the dataset and the `scripts/fetch_data.py` command that downloads it. | [standard] |
| `PTM_SPICE_KERNELS` | unset | Overrides the SPICE kernel directory when none is set in the config or on the command line. The directory is chosen in this order: the explicit setting, this variable, `$PTM_DATA_ROOT/kernels`, and the compiled-in `SPICE_KERNELS_DIR` (default `<repo>/data/kernels`). The first two are taken exactly as given. The last two are skipped if they contain no `lsk/naif0012.tls`, so a fresh clone or worktree, which has the `*.tm` files but not `lsk/`, can still find a kernel tree through `$PTM_DATA_ROOT`. Every run prints the directory it chose and where the choice came from, and any SPICE failure lists the candidates in order. | [standard] |
| `PTM_ALBEDO_MAPS_DIR` | unset | Overrides the directory of albedo and property FITS maps, which is otherwise the config's `albedo_maps_directory`. | [standard] |
| `PTM_MACHINE_PROFILE` | `~/.ptm3d/machine_profile.json` | Path to the per-host GPU machine profile written by `--calibrate-gpu`. | [standard] |
| `TMPDIR` | `/tmp` | (POSIX, not `PTM_*`.) Used for the H-matrix out-of-core scratch files. | [standard] |

## Illumination (shadow-ray corrections)

| Variable | Default | Effect | Status |
|---|---|---|---|
| `PTM_ILLUM_TRUE_NORMALS` | off | Uses the normals given by the mesh's triangle winding for illumination, instead of flipping each normal to point radially upward. On polar terrain the radial flip inverts ~97% of steep-wall faces and produces sunlit overhangs that do not exist. With this setting the false overhang tail above 380 K is removed and no sunlit face is darkened. The setting is ignored, with a printed message, on a smooth global icosphere. Such a mesh uses analytic radial normals, which remove a bias at the pentagon vertices, and it has no overhang faces to correct. The startup line reports how many normals were overridden, or that the override was not applied. | [recommended-ON] `=1` |
| `PTM_ILLUM_RISE_EPS` | off | Separates a face's own mm-scale relief from a real occluding rim by the height a shadow ray rises out of the face plane, instead of by the default 1 cm ray offset. The fixed offset can step over real rims and illuminate permanently shadowed faces. Use it only together with `PTM_ILLUM_RISE_HABS=0`. The status tags above give the effect of setting it alone. | [recommended-ON] `=1`, with `RISE_HABS=0` |
| `PTM_ILLUM_RISE_KEPS` | 0.2 | Fraction of the facet edge that sets the edge-proportional self-relief floor for RISE_EPS. It has no effect when `PTM_ILLUM_RISE_HABS=0`, because the absolute floor replaces it. | [recommended-ON] leave at `0.2` |
| `PTM_ILLUM_RISE_HABS` | unset (edge-proportional) | Absolute self-relief floor in meters, replacing the edge-proportional one. `0` excludes only the source triangle itself. With `=0`, all of the grazing-incidence light leaks are removed and no spurious self-shadowing speckle appears. | [recommended-ON] `=0` |
| `PTM_ILLUM_SEAL_HOLES` | off | Fills interior holes in the mesh with shadow-only faces, which are never solved or written, so that rays sampling the finite solar disk cannot pass through gaps in the mesh (the "crater-center flash"). On a 509k-face lunar polar mesh this added 49 shadow-only faces and removed the flash, with one collateral face in 778. | [recommended-ON] `=1` |
| `PTM_ILLUM_RISE_EPS2` | off | A multi-hit refinement mode ("option 3") that implies RISE_EPS. It does not remove the spurious illumination on its own, and the combination of RISE_EPS with RISE_HABS=0 is used instead. | [experimental] |
| `PTM_ILLUM_RISE_BARY_EPS` | internal default | Barycentric tolerance for the RISE_EPS source-triangle exclusion. | [tuning] |
| `PTM_ILLUM_TOPO_SELFSKIP` | off | Alternative mitigation: topological self-skip of the source face's neighborhood. It applies to CPU illumination only and has no effect on the GPU ray tracer. | [experimental] |
| `PTM_ILLUM_SELFSKIP_RINGS` | 1 | Neighborhood ring count for TOPO_SELFSKIP. | [experimental] |
| `PTM_ILLUM_HORIZON_CULL` | off | Heightfield-horizon pre-cull of shadow rays. | [experimental] |
| `PTM_ILLUM_HORIZON_SLACK_DEG` | internal default | Slack angle for HORIZON_CULL. | [experimental] |
| `PTM_ILLUM_HORIZON_CELL_SCALE` | internal default | Heightfield cell scale for HORIZON_CULL. | [experimental] |
| `PTM_DISABLE_STRICT_HORIZON` | 0 | `=1` disables strict outward-normal enforcement when computing face geometry. For debugging. | [internal] |

## Thermal equilibration

| Variable | Default | Effect | Status |
|---|---|---|---|
| `PTM_EQ_PERFACE_FLUX` | off | Affects only the legacy GPU seed (`thermal.spinup_seed: legacy`). It seeds each column from its own time-mean absorbed flux plus Q_b, instead of the instantaneous flux of the first ten steps with a 100 K nightside floor. It has no effect under the default `physical` seed, which does this on every solver. | [legacy] |
| `PTM_CPU_RETHERMAL` | `seed-series` | How a re-thermal pass of the CPU coupling loop starts its columns. `seed-series` (default) re-seeds with the indirect-aware series seed of `thermal.seed_indirect`. `reseed` uses the warm-bracket re-seed. `resume` restores the end-of-spin-up state of the last whole-mesh pass and integrates only the output window. Under the opt-in `thermal.seed_window: eq_span`, `seed-series` and `reseed` both seed the pass from its own equilibration forcing instead, and the log reports this. The default `auto` and `legacy` settings of that key keep the behavior described here. Any other value stops the run with an error. Recorded in `provenance.txt` as `cpu_rethermal`. | [standard] |
| `PTM_GPU_FLUX_FORCING` | unset (config wins) | Overrides `thermal.gpu_flux_forcing`: `interpolate` (default) or `hold`, which holds each interval's starting flux, is kept for reproducing older GPU runs, and prints a warning. Any other value stops the run with an error. Recorded in `provenance.txt` as `gpu_flux_forcing`. | [standard] |
| `PTM_GPU_RETHERMAL` | unset (config wins) | Overrides `thermal.gpu_rethermal`: `seed_series` (default), which re-seeds and re-equilibrates on every coupling pass as the CPU solver does, or `resume`, which is kept for reproducing older GPU runs and prints a warning. Any other value stops the run with an error. Recorded in `provenance.txt` as `gpu_rethermal`. | [standard] |
| `PTM_SPINUP_SEED`, `PTM_SEED_ANCHOR`, `PTM_SEED_WINDOW`, `PTM_SEED_SEASONAL`, `PTM_ANALYTIC_SEED_CYCLES` | unset (config wins) | Override `thermal.spinup_seed`, `thermal.seed_anchor`, `thermal.seed_window` (also over `--seed-window`), `thermal.seed_seasonal` (also over `--seed-seasonal`) and `thermal.analytic_seed_cycles` (see [configuration.md](configuration.md)). | [standard] |
| `PTM_EQ_WITH_INDIRECT` | off | Includes the (phase-mapped) indirect radiation flux in the re-equilibration of coupled seasonal runs. It differs from `thermal.eq_indirect_source`, which corrects the initial whole-mesh equilibration once. This variable re-equilibrates the selected faces inside every coupling iteration. The two can be combined, since each acts on a different phase, but the combination has not been characterized. | [experimental] |
| `PTM_EQ_INDIRECT_CYCLES` | 2 | Number of prior seasonal cycles assumed stationary for the EQ_WITH_INDIRECT phase mapping. | [experimental] |
| `PTM_EQ_RETHERMAL_BATCH` | 4000 | GPU batch cap during EQ_WITH_INDIRECT re-equilibration. The 50k default exceeds the command-buffer time limit of the macOS/AMD GPU driver. | [tuning] |
| `PTM_EQUILIBRATION_CYCLES` | unset (config wins) | Number of passes over the equilibration forcing array, GPU persistent solver only. Overrides `thermal.equilibration_cycles`. The solver's own value is 2. Must be an integer ≥ 1, and any other value is reported as an error. | [standard] |
| `PTM_EQ_LEGACY_SEED` | unset | Not read by the model. Setting it changes no result, and the CPU batch solver prints a warning that names it. | [internal] |
| `PTM_RETHERMAL_WARMUP_SKIP` | 0 | Number of leading output steps of a coupling re-run that keep the uncoupled iteration-0 temperature. `=2` reproduces the mask used before v1.0.3. | [internal] |

## Radiation exchange / radiosity

| Variable | Default | Effect | Status |
|---|---|---|---|
| `PTM_RAD_TWO_BAND` | unset | Alternative way to enable band-separated radiosity, which is the default through `radiation.band_separated: true`. The visible band scatters with the Bond albedo, the IR band with 1−ε, and the absorbed indirect flux is their sum. It requires `PTM_SOLAR_ALBEDO`. Without a per-face Bond albedo the request prints a warning and the solution stays gray. Set `radiation.band_separated: false` for a single gray band. | [standard] |
| `PTM_LEGACY_RADIOSITY_STATIC_ALBEDO` | 0 | `=1` builds the two-band visible source from the static base albedo instead of the incidence-angle albedo used in the surface boundary condition. Energy is then not conserved at grazing incidence, and a warning is printed. For comparison tests only. | [internal] |
| `PTM_LEGACY_ALBEDO_NORMAL_A0` | 0 | Has no effect. With the per-face single-scattering albedo, the Hapke normal-incidence branch returns the same value as the continuous branch. A message is printed when it is set. | [internal] |
| `PTM_LEGACY_FIXED_SOLARCONST` | 0 | `=1` uses the fixed 1 AU solar constant in place of the instantaneous value at each time step, which reproduces results from before v1.0.3 exactly. | [internal] |
| `PTM_HMATRIX_VF_REPLACE_GPU` / `PTM_HMATRIX_VF_REPLACE_CPU` | unset (the config decides) | Override which radiosity solver receives the matrix given by `PTM_HMATRIX_VF_REPLACE`. Neither is normally needed, because the choice follows `radiation.use_gpu` and is printed on stdout (`[PTM_HMATRIX_VF_REPLACE] ROUTE = GPU/CPU (…)`). Setting both stops the run with an error, since they select opposite solvers. The GPU and CPU solvers do not give identical temperatures. Compared with the CPU solver in the same run, the largest temperature difference was 6.6 mK on a lunar polar mesh with weak coupling (max ΣF = 0.2) and 0.27 K on the 509k Moon3D testbed mesh with strong coupling. The differences are almost all of one sign (99.6–99.9 %), which indicates truncation and single-precision arithmetic, not symmetric round-off. The matrix is installed as the CPU operator first and moved to the GPU only in `initGPU()`, so a run that cannot use the GPU continues with the CPU solver. See [radiation-exchange.md §6.6](radiation-exchange.md). | [experimental] |
| `PTM_RADIOSITY_CHUNK_NNZ` | auto (2.0 GB per buffer) | Lowers the cap on stored entries per chunk of the chunked GPU sparse product. The automatic value leaves margin below the 2 GB limit on a single allocation. Lower it only to reproduce a particular chunk split. | [internal] |
| `PTM_RAD_FORCE_SINGLE_FAIL`, `PTM_RAD_FORCE_POOL_FAIL` | unset | Fault injection for testing. Forces the single-GPU or multi-GPU radiosity initialization to fail so that the fallback can be exercised. | [internal] |
| `PTM_RAD_GPU_CHECK_INTERVAL` | unset (auto) | Fixes the interval at which the GPU Jacobi radiosity iteration checks convergence, overriding both `RadiationConfig::convergence_check_interval` and the automatic choice for each matrix (`resolveConvergenceCheckInterval`: every iteration above ≈7.6e7 stored non-zeros, every 10 below, as described in [radiation-exchange.md §6.4](radiation-exchange.md)). This changes how many Jacobi iterations run, and therefore the results, unless the solve has already stagnated. A message is printed at startup. It allows the automatic choice to be tested at a new mesh size without recompiling. | [internal] |
| `PTM_SOLAR_ALBEDO` | unset | Bond albedo for the reflected-solar radiosity source (e.g. `0.12` for the Moon). Without it the solar source scatters with the thermal reflectivity 1−ε (~0.05), which is too low for sunlight. Also used by `PTM_BEAM_SOLAR`. | [standard] (set with TWO_BAND) |
| `PTM_RAD_EMISSIVITY` | unset | Forces a uniform radiosity emissivity (consistency studies). | [internal] |
| `PTM_RAD_ITER_TRACE` | unset | Traces the radiosity solve with one stderr line per Jacobi sweep: `dB_abs` (max\|B_new−B_old\| in W/m², the quantity the GPU criterion tests), `B_max`, and their ratio `rel` (the quantity the CPU criterion tests). The two solvers apply the same configured tolerance to different quantities, and the trace shows both. While set, it changes GPU behavior. It forces a convergence check on every iteration, overriding the interval that `resolveConvergenceCheckInterval` chose for the matrix, so each solve stops on the iteration at which it converges and the iteration counts differ from those of a normal run. A message is printed next to the interval line. Use `PTM_RAD_COST_REPORT` alone to obtain the cost of a normal run. Also prints the `[rad-cost]` summary. | [internal] |
| `PTM_RAD_ITER_TRACE_FULL` | unset | With `PTM_RAD_ITER_TRACE`, also suppresses the early exit and runs every solve to `max_iterations`, which shows the decay of the residual beyond the normal stopping point. Diagnostic runs only. It changes results. | [internal] |
| `PTM_RAD_GPU_FUSE_BANDS` | 1 (on) | The GPU band-separated radiosity solve reads each view-factor row once and advances both bands, as the CPU solver does. `=0` selects two separate solves over the same matrix, with roughly twice the matrix traversals and the same result. The arithmetic in each band is unchanged, so the two options give bit-identical results. `test_two_band_rownorm` section B1f checks this by comparing both bands exactly. A message is printed when it is turned off. | [kill-switch] |
| `PTM_RAD_GPU_ABS_CRITERION` | unset | `=1` selects the legacy GPU stopping test, max\|dB\| < max(tol, 1e-5) W/m², in place of the relative test max\|dB\|/max\|B\| < tol used by the CPU solver. At B ≈ 900 W/m² the absolute test is ~900× stricter, so the GPU runs more Jacobi sweeps than the CPU for the same tolerance. For diagnosis only. A message is printed when it is set. | [debug] |
| `PTM_RAD_COST_REPORT` | unset | Prints one `[rad-cost]` line at exit with the number of radiosity solves, the total view-factor-matrix traversals, and the total wall time inside the solver. It does not perturb the solve. Whole-run wall time cannot separate radiosity from illumination and thermal work on a shared machine, so use this line to compare radiosity cost. The counters are incremented in `RadiositySolver::solve()`. A multi-timestep `solveBatch()` that goes directly to the multi-GPU pool does not pass through `solve()` and contributes nothing to `solves`/`wall`. Single-timestep solves, the serial batch fallback, and every CPU solve are counted. | [internal] |
| `PTM_BEAM_SOLAR` | 0 | Smith-style beamed reflected-solar emission on wall-to-floor pairs. | [experimental] |
| `PTM_RAD_COUPLING_RELAX` | 1.0 | Picard under-relaxation ω for the thermal-radiation coupling loop. A safeguard for meshes on which the unrelaxed loop converges poorly. | [tuning] |
| `PTM_COUPLING_MODE` | unset (config wins; config default `bounded`) | Overrides `radiation.coupling_mode` = `bounded` \| `fixed` \| `legacy` without editing the config, so that a run made with another coupling mode can be reproduced exactly. The value is checked when the configuration is read, and an unrecognized value stops the run with an error before the illumination pass. See `docs/radiation-exchange.md` § "Chunk-decomposition independence". | [standard] |
| `PTM_EQ_INDIRECT_SOURCE` | unset (config wins; config default `auto`) | Overrides `thermal.eq_indirect_source` = `auto` \| `converged` \| `off` without editing the config, so that a run made with another setting can be reproduced bit for bit. `auto` estimates the per-face mean indirect flux from the iteration-0 sweep of the coupling loop and adds it to the equilibration forcing. `converged` reads it after the coupling loop converges, which removes the low bias of the iteration-0 estimate and costs one extra coupling loop per pass. `off` adds no indirect flux to the equilibration forcing. A non-empty `thermal.eq_indirect_flux_file` overrides all three. An unrecognized value stops the run with an error at startup. See `docs/radiation-exchange.md` § 7.7. | [standard] |
| `PTM_EQ_INDIRECT_PASSES` | unset (config wins; config default `1`) | Overrides `thermal.eq_indirect_passes`, the number of times the internal estimate is refreshed and the equilibration repeated. The default `1` is a single pass. A second `auto` pass is the point of diminishing returns for that estimator, but it improves the estimate far less per second of run time than `PTM_EQ_INDIRECT_SOURCE=converged` does. Must be ≥ 1. `0` is rejected and is not an alias for `off`. A non-integer value stops the run with an error. See `docs/radiation-exchange.md` § 7.7. | [standard] |
| `PTM_EXCHANGE_SELECTION` | unset (config wins; config default `all`) | Overrides `radiation.exchange_selection` = `all` \| `shadow` without editing the config, so that a run made with the other setting can be reproduced exactly. `shadow` applies a shadow-fraction test over the run window, which sets the indirect flux to zero on faces that are sunlit within that window. The run prints a warning with the number of such faces. The value is checked when the configuration is read, and an unrecognized value stops the run with an error before the illumination pass. See `docs/radiation-exchange.md` § "The radiation-exchange face set". | [standard] |
| `PTM_RAD_SKIP_EQ_STEPS` | 1 (on since 2026-08-15) | The radiosity sweep of the coupling loop starts at the first output step instead of at t=0, so the equilibration span is not solved. On a two-phase run the whole-mesh GPU solver records surface temperatures over the output window only. Radiosity solves in the equilibration span would then see a 0 K surface, and nothing uses their result. Skipping them reduced the wall time of a full 509k-face lunar run by 46.5 % (3000 equilibration and 20 output steps). Together with the default-on `PTM_RAD_SELECT_OUTPUT_WINDOW`, the skip left all 22 `statistics/*.bin` files of that run unchanged. `=0` restores the sweep over the whole span. The equilibration span is required when `thermal.use_gpu` is false, when the run is single-cadence, when there is a location export, or when a coupling iteration falls back to the CPU re-thermal. With an explicit `=1` the run stops with an error in each of those cases. At its default the skip is not applied in those cases and the log gives the reason. The exception is a fallback to the CPU re-thermal in the middle of the coupling loop, which always stops the run because by then the span has not been solved (re-run with `=0`). | [kill-switch] |
| `PTM_RAD_SELECT_OUTPUT_WINDOW` | 1 (on since 2026-08-15), gated | Restricts the maximum indirect flux used by the coupling loop's face selection to the output window `[equilibration_steps, total)`. The selection passes that maximum to a linearized estimate of the temperature response in the output window. On a two-phase run the equilibration span is solved with the enclosure at 0 K, where only reflected sunlight is present, so a maximum taken over all time steps can be set by that span. On a 509k-face lunar mesh the equilibration span held the maximum on 35.5 % of faces. The default therefore applies only to the two-phase GPU re-thermal. On a single-cadence run or the CPU re-thermal the solver records every step, the equilibration span carries real temperatures and inter-face IR, and the re-thermal integrates it again, so restricting the maximum would select too few faces. There the restriction is not applied and the log reports this. An explicit `=1` is honored in those cases, with a warning. `=0` takes the maximum over the whole span everywhere, which changes the results of a two-phase GPU run. The cost is negligible either way. | [kill-switch] |
| `PTM_RHO_ADVISORY` | 1 (on) | Before the first coupling sweep, applies power iteration to the view-factor operator that the solve uses (`diag(1/max(1, Σ_j F_ij))·F`, since the radiosity renormalizes every row of `F·x`, not raw `F`). It reports ρ, the implied Picard rate `r = ε·ρ/(1−(1−ε)·ρ)` at the radiosity emissivity in use, and an upper bound on the sweeps needed for a 1 K and a 0.1 K coupling increment. A warning is printed when `radiation.max_coupling_iterations` is below the 1 K count. The estimate is advisory and changes no result. It runs for coupled runs only and is skipped when `max_coupling_iterations < 2`. It costs one matrix-vector product per iteration for at most 60 iterations, about 3.0 s at 495M non-zeros on 48 cores, which is well under 1 % of one coupling sweep on that mesh. `=0` skips it and prints a message. | [kill-switch] |
| `PTM_HMATRIX_VF_REPLACE` | unset | Replaces the stored view-factor matrix with a precomputed one (a sparse-matrix file from the offline view-factor referee, with row sums ≤ 1 and reciprocity preserved). The program stops if the face count or geometry hash does not match the mesh. It also stops (exit 3) if the matrix was traced on the opposite side of the surface from the one the run illuminates. The orientation recorded in the matrix's `.provenance.json` is compared with that of the run (`radial_per_face` by default, `winding_majority` under `PTM_ILLUM_TRUE_NORMALS=1`). A matrix with no recorded orientation was traced along the raw winding and is accepted only where that equals the run's orientation on every face. The matrix goes to the GPU or CPU radiosity operator according to `radiation.use_gpu`. | [experimental] |
| `PTM_VF_ORIENT_OVERRIDE` | unset | `1` lets a run proceed with a `PTM_HMATRIX_VF_REPLACE` matrix that fails the surface-side check, with a warning. Radiation exchange in such a run is physically inconsistent with its illumination. Use it only to reproduce a legacy run exactly. | [debug] |
| `PTM_PP_ORIENT` | `engine` | Face orientation used by the view-factor referee (`mc_ref_pp`). `engine` (default) applies the orientation criterion of the thermal model from `src/cpp/mesh/face_orientation.h`, selected by the same `PTM_ILLUM_TRUE_NORMALS` variable. `raw` traces the raw winding, which gives the underside of an inward-wound mesh. It is for comparison tests and for reproducing old matrices, and prints a warning. Any other value stops the calculation with an error. | [debug] |
| `PTM_PP_ORIENT_EXPECT_REVERSAL` | unset | `1` acknowledges that the referee's orientation criterion reverses more than `PTM_PP_ORIENT_MAX_REVERSED_PCT` of the faces relative to the raw winding, as on an inward-wound mesh such as the Moon3D 509k crater. Without it the calculation stops with an error (exit 5) before tracing. | [standard] |
| `PTM_PP_ORIENT_MAX_REVERSED_PCT` | `1` | Percentage of faces the referee's orientation may reverse relative to the raw winding before `PTM_PP_ORIENT_EXPECT_REVERSAL=1` is required. | [debug] |
| `PTM_HMATRIX_ROWFIX` | unset | Row-sum correction for over-counted view factors: a symmetric rescaling of the matrix (D·F·D), iterated (Sinkhorn algorithm) until each face's total view factor matches a reference value supplied as a file of n double-precision numbers. If the iteration does not converge, the program stops with an error. | [experimental] |
| `PTM_HMATRIX_ROWFIX_MODE` | `damp` | `damp` applies reductions only and is stable and validated. `full` also restores under-coupling but diverges on this class of problem, and the convergence check stops the run. Use `damp`. | [experimental] |
| `PTM_HMATRIX_ROWFIX_RCAP` | 4.0 | Full-mode cap: restoration ≤ RCAP×stored per row. | [experimental] |
| `PTM_HMATRIX_ROWFIX_DMAX` | 4.0 | Clamp on the congruence diagonal d. | [experimental] |
| `PTM_HMATRIX_ROWFIX_RELAX` | 0.5 (damp) / 0.25 (full) | Sinkhorn under-relaxation. | [experimental] |
| `PTM_HMATRIX_ROWFIX_TOL` | 1e-2 | Convergence tolerance. Loosening it is not recommended. | [experimental] |

## H-matrix view-factor build

## Memory and GPU dispatch

| Variable | Default | Effect | Status |
|---|---|---|---|
| `PTM_RAM_ILLUM_MAX_GB` | 10 | Threshold (GB) above which the illumination time series is streamed from the chunked store instead of being held in memory. Raise it on high-memory machines and lower it on laptops. It selects only the source of the forcing. Above the threshold the CPU run uses the configured integrator (SIMD batch by default, fed one 8-face tile at a time, or the scalar one with `--no-simd-batch`). The thermal field is the same by construction, since the solver, seed and boundary conditions are the same, and whole run directories were identical on a 12,800-face crater at 80°N and an 81,920-face lunar ico6 mesh. The illumination statistics use a separate streamed reduction, which those two comparisons also covered but which is not guaranteed to be identical in general. `[thermal-solver] PATH:` in the log and `thermal_solver_core` in `provenance.txt` state which integrator ran. | [tuning] |
| `PTM_MAX_TIMESTEPS_PER_DISPATCH` | machine profile, else 300 | Upper limit on the number of thermal time steps in one GPU work submission, which protects against GPU driver timeouts. Normally supplied by `--calibrate-gpu`. Setting it explicitly also disables the inline auto-calibration probe. | [tuning] |
| `PTM_NO_AUTO_CALIBRATE` | unset | Disables the inline GPU auto-calibration probe (`thermal.auto_calibrate_gpu`, default on), so that the machine-profile or conservative limit is used. It affects only how the work is divided among GPU submissions, not the physics. | [tuning] |
| `PTM_LOG_SUBDISPATCH` | off | Logs the timing of each GPU work submission, for diagnosing GPU driver hangs. | [internal] |
| `PTM_GPU_MIN_VRAM_MARGIN_GIB` | config `gpu.min_vram_margin_gib` (2.0) | Minimum free memory, in GiB, that a radiosity matrix copy held on a GPU must leave on that device. Overrides the config key, prints a message, and enforces the minimum on every platform (the config default is enforced only on macOS+AMD and is advisory elsewhere). A malformed value prints a warning and is ignored. `0` applies only the check that the matrix fits. See [gpu-wedge-guardrails.md](dev/gpu-wedge-guardrails.md). | [tuning] |
| `PTM_RAD_RERUN_MAX_GPUS` | configured thermal device count | Lowers the number of devices used by the selected-faces re-thermal of the radiation coupling. `=1` runs it serially on one device. By default all configured thermal devices are used. A non-positive value prints a warning and is ignored. | [tuning] |
| `PTM_GPU_FORCE_WEDGE_PLATFORM` | unset | Test setting for the platform check. `=1` treats the host as macOS+AMD, where the GPU safeguards are enforced, and `=0` treats it as a platform not prone to driver hangs, where they are advisory. A message is printed on stdout. It allows both branches of the memory-margin and placement policies to be exercised on one machine. | [internal] |
| `PTM_GPU_POWER_PROBE_FILE` | unset | Test setting for the macOS power-settings advisory. This file is read instead of running `pmset -g custom`. A message is printed. | [internal] |

## Diagnostics and internal tooling

| Variable | Default | Effect | Status |
|---|---|---|---|
| `PTM_BVH_HOST_KERNEL` | unset | `1`: the GPU illumination code traces its shadow rays on the host CPU, using the same kernel source as the device (`src/cpp/gpu/bvh_shadow_kernel.inc`). This gives a reference for the device result, which can be used to validate GPU illumination without a GPU and to detect device compiler errors. Slow. Prints a warning. | [internal] |
| `PTM_GPU_DISPATCH_TARGET_S` | 1.5 | Wall-time budget, in seconds, against which every GPU thermal work submission is sized. Overrides `gpu.dispatch_target_s`. The accepted range is 0.1-10, and any other value prints a warning and is ignored. It affects only where the work is divided, and results are identical for any value. The adaptive sizing aims at 0.9 of the budget, which leaves headroom for the cost per step rising between chunks, so the budget acts as a ceiling. The resolved value and its source are printed at startup and written to `provenance.txt`. `PTM_MAX_TIMESTEPS_PER_DISPATCH` overrides the adaptive sizing entirely. | [tuning] |
| `PTM_LOG_GPU_DISPATCH` | unset | `1`: prints `[gpu-dispatch]` timing lines for GPU work. There is one line per GPU illumination (BVH) dispatch (rays and upload, kernel and total ms), per pause between batches, per GPU thermal batch, per radiation re-thermal pause, and per GPU radiosity solve (wall time of the whole solve, which spans many kernels and is an upper bound per dispatch). For a thermal batch, the single-device loop reports the batch wall time and the multi-device pool reports the work time and the pause. The multi-GPU radiosity pool adds one line per device per batch (`path=radiosity-pool`, with work_ms and the pause), one per batch from the solver (`path=radiosity-batch-host`, with host setup and the wait on the devices), and one per batch from the coupling sweep (`path=radiosity-sweep-batch`, with input preparation, the batch call, and the write-back). A sweep's wall time can then be divided into device work, pause and host time. The lines are used to size the pauses and batches against the dispatch budget (`PTM_GPU_DISPATCH_TARGET_S`). The thermal equivalent is `PTM_LOG_SUBDISPATCH`. Pair with `scripts/gpu_telemetry.py` for per-die temperature and power. The host-side cost of the GPU direct-solar calculation is also printed per frame (`path=illum-frame`, with direct solar, primary IR, reflected, store), per direct-solar pass (`path=illum-direct-gpu`, with preparation, ray build, trace, and assembly of the center and disk passes), and per tracer call (inverse directions, upload, kernel, readback, overflow check). The host-side seeding of each GPU thermal batch is reported as `path=thermal-seed` (faces, seed_ms). | [internal] |
| `PTM_LOG_PRIMARY_VIS_HASH` | unset | `1`: one `[primary-vis-hash]` line per evaluated epoch of the primary-disk (Earthshine/planetshine) visibility pass, with FNV-1a hashes of the per-face visibility, distance and terrain arrays and the ray count. Compare these lines to confirm that a change to how those rays are traced or summed leaves the arrays unchanged. The arrays are double precision and feed the primary IR and reflected light directly, and a change in their last bit is not visible in the single-precision outputs. Test only. | [internal] |
| `PTM_LOG_GPU_RAYHASH` | unset | `1`: one `[gpu-dispatch] path=rayhash` line per GPU direct-solar batch, with FNV-1a hashes of every per-ray input array (origin, direction, tnear, rise-epsilon inputs, skip facet) and of the occlusion result. Compare the lines from two versions of the program to confirm that a change to host-side GPU ray preparation leaves the rays unchanged. Comparing outputs is not sufficient, because a change of one unit in the last place of one ray per batch can leave every output byte unchanged. Costs a serial pass over the batch. Test only. | [internal] |
| `PTM_BVH_DUMP_DIR` / `PTM_BVH_DUMP_PRIMS` | unset | For diagnosing GPU illumination. Given a directory and a comma-separated list of source-facet indices, every BVH tracer writes the single-precision geometry it uploaded (`mesh_f32.bin`) and appends each traced ray whose source facet is listed, with its parameters and result (`rays.bin`, with the layout given in `src/cpp/gpu/bvh_opencl.cpp`). Used to examine individual disagreements between GPU and CPU. Prints a warning. | [internal] |
| `PTM_OPENCL_DEVICE_TYPE` | unset | `cpu`: the GPU pools enumerate the OpenCL CPU device instead of GPUs. Prints a warning. On macOS that device does not execute the BVH shadow kernel correctly, so do not use it to judge illumination results. Use `PTM_BVH_HOST_KERNEL=1` instead. | [internal] |
| `PTM_BVH_CL_OPTIONS` | unset | Build options for the BVH shadow kernel. The default is none, and `-cl-fast-relaxed-math` is not used. Prints a warning. | [internal] |
| `PTM_DUMP_EQ_SEED` | unset | Writes a per-face CSV of the equilibration seed of the CPU batch solver (`avg_flux`, `T_surf_est`, `T_deep - T_surf_est`) and of the analytic clear-sky forcing that drove the equilibration (`eq_forcing_mean/max`), plus each face's final surface temperature. Written once at the end of the batch solve. When unset there is no cost and the output is unchanged. | [internal] |
| `PTM_DUMP_VF_ROWSUMS` | unset | Write each face's total view factor ΣF to the given path (binary: a 4-byte count, then n double-precision values). | [internal] |
| `PTM_DUMP_QIND_SERIES` | unset | Write the per-face indirect-flux time series (binary, 'QIDT' marker, then single-precision values, all timesteps of face 0, then face 1, ...). | [internal] |
| `PTM_DUMP_REFLIR` | unset | Write each face's peak temperature and the indirect flux at that moment (binary, 'RFIR' marker). | [internal] |
| `PTM_VF_ROBUST`, `PTM_VF_NLIFT`, `PTM_VF_MSAMPLE`, `PTM_VF_IGNORE_NEAR`, `PTM_VF_MC_LIFT` | unset | Settings for the standalone view-factor checking tools (`vf_face_probe`, `vf_hemisphere_mc`), which recompute individual view factors by independent Monte Carlo ray tracing for comparison. | [internal] |
| `PTM_PRIMARY_DISK_ALWAYS_SAMPLE` | 0 | `=1` disables the convex-body shortcut in the finite primary-disk visibility test, so every face uses the full sample count. For validation. | [internal] |
| `PTM_PRIMARY_DISK_STATS` | 0 | `=1` prints a count of faces by primary-disk branch (below horizon, fully lit, dark, sampled). | [internal] |
